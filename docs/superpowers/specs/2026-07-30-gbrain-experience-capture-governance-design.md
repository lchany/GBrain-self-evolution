# GBrain 经验总结与审核规则设计

## 目标

客户端在执行非平凡任务和处理故障时主动召回既有经验，但不能把“召回”
误解为“自动写入”。候选经验只有在完成脱敏、去重、固定模板整理和正文
审核后，才能通过 MCP `put_page` 写入 `inbox/`。

经验正文一旦经过写入前审核就保持不变。后续人工审核只调整分类、标签、
目标目录和审核状态；如果正文需要修改，应拒绝当前草稿，重新生成并再次
进行写入前审核。

面向用户的规则、说明、标题和总结默认使用中文。命令、代码、路径、协议
字段、错误原文和无法准确翻译的专有名词保留英文。

## 方案选择

### 方案一：只修改本地 AGENTS.md

修改快，但下一次运行安装器就会被旧模板覆盖，也无法防止 Codex 和
OpenCode 的技能内容继续漂移。不采用。

### 方案二：修改安装器生成源、测试和文档，再重新安装本地配置

项目代码成为唯一生成源，Codex 与 OpenCode 得到一致规则，测试可以阻止
门禁和模板回退。采用此方案。

### 方案三：由 MCP 服务端强制审批凭据

能够提供不可绕过的硬门禁，但需要新增服务端状态、审批凭据和协议字段，
超出本次客户端规则修复范围。将来只有在客户端规则门禁不足时再单独设计。

## 触发规则

### 非平凡任务

满足下列任一条件时，任务属于非平凡任务：

- 包含多个有依赖关系的执行步骤；
- 修改代码、配置、数据、服务器或外部系统；
- 涉及部署、迁移、调试、架构、安全或隐私判断；
- 包含会影响后续工作的客户要求、项目规则、偏好或约束；
- 具有明显成本、风险或难以撤销的影响。

收到非平凡任务后，客户端自动执行只读召回，并把结果分类为“直接适用”、
“部分适用”或“不适用”。只读召回使用 `search`、`query` 和 `get_page`，
不需要人工确认，也不允许因此直接调用 `put_page`。

### 执行失败

只有意外失败影响任务目标，并且发生阻塞、重复出现、改变执行策略或可能
形成可复用故障经验时，才触发故障召回。

以下情况不计入需要总结的执行失败：

- 预期失败测试；
- 用于探测状态的正常否定结果；
- `rg` 没有匹配；
- 立即修正的命令拼写或引号错误；
- 一次重试即恢复且没有复用价值的瞬时故障。

相同或高度相似的失败场景出现第 2 次时，客户端必须停止盲目重试并整理
错误总结。相同场景由任务阶段、工具或命令、错误码或关键报错、环境条件
以及已知根因共同判断。未改变任何条件的连续重试只算一次故障事件；跨
任务、跨运行，或经过有效干预后再次发生，才增加发生次数。

## 写入前审核

以下候选内容默认必须在 `put_page` 前进行人工审核：

- 客户要求、项目规则、偏好和约束；
- 任务总结和项目里程碑；
- 重复故障、失败总结、根因和解决办法；
- 新增或实质更新的知识、runbook 和决策记录。

客户端先搜索重复记录，再按固定模板生成脱敏预览。预览至少包含标题、
建议类型、建议目标位置、适用与不适用场景、正文、证据指针、验证状态和
脱敏说明。用户明确同意该预览，或者完整预览展示后 5 分钟内没有任何
回复，客户端才能调用 `put_page`。

展示预览时，客户端必须明确告知用户：“如需拒绝或修改，请在 5 分钟内
回复；5 分钟没有回复将继续写入 `inbox/`。”用户在等待期内拒绝或要求
修改时，不写入、不离线排队。用户在完整预览展示后的 5 分钟内没有任何
回复时，视为允许写入，客户端继续调用 `put_page`。

用户在等待期内发送任何消息都会结束静默等待。只有明确同意才能立即写入；
拒绝或要求修改时不写入；回复内容无法判断是否同意时，客户端继续澄清，
不能把它当作静默超时。修改后的正文必须重新完整展示，并从展示完成时
重新计算 5 分钟。

如果客户端运行环境不支持等待后自动继续执行，不得伪造已经等待或已经
写入。客户端应在下一次获得执行机会时检查完整预览展示后是否已经超过
5 分钟，并确认期间没有用户回复，再继续写入。

用户可以明确免除写入前逐条确认。除非用户明确指定全局持续生效，免审只
适用于当前任务、会话或项目。免审不取消脱敏、搜索去重、固定模板、
`inbox/` 限制和后续晋升审核。

## 预分类与内容锁定

客户端在写入前给出以下预分类建议：

- `type`；
- 建议目标目录和 slug；
- 适用范围：当前项目、指定仓库、指定环境或跨项目；
- 标签和召回关键词；
- 验证状态和置信度；
- 与既有记录的关系：新增、合并、替代或冲突。

预分类不等于最终分类。正文确认并写入后，后续审核可以调整 `type`、标签、
目标目录、slug 和审核状态，但不得改动正文、证据、适用条件、不适用条件
或验证结果。

如果审核者发现正文错误或证据不足，应执行“拒绝”或“需要补充证据”，并
说明原因。客户端随后生成新版本，重新经过正文审核和 `put_page` 写入。
审核阶段不得静默修复正文。

## 客户端技能职责

### `gbrain-capture`

- 在非平凡任务开始和关键失败后进行只读召回；
- 在第 2 次同类故障时强制生成错误总结；
- 搜索重复记录并区分新增、合并和更新；
- 生成固定模板、完成脱敏并提供预分类；
- 在 `put_page` 前等待用户确认或 5 分钟静默超时；
- 只写 `inbox/`，不直接写最终分类目录。

### `gbrain-review`

- 从 `inbox/` 读取已确认正文；
- 核对模板完整性、证据和预分类；
- 只调整分类相关元数据；
- 正文有问题时拒绝或退回，不直接修改；
- 不自动晋升，匿名 MCP 客户端不执行晋升。

### AGENTS.md 管理块

- 用短规则描述召回、重复故障、写入前确认、中文优先和正文锁定；
- 把详细模板留在 `gbrain-capture`，避免全局规则过度膨胀；
- 保留隐私、纯 MCP、无本地队列和防火墙访问边界。

## 测试

先修改 `test/gbrain-client-installer.test.ts`，让测试在旧实现上失败，再修改
安装器内容使其通过。测试至少固定以下行为：

- Codex 和 OpenCode 都安装相同的中文优先规则；
- 非平凡任务和关键失败只触发只读召回；
- 第 2 次同类故障触发强制错误总结；
- `put_page` 前要求展示完整预览，并等待明确确认或 5 分钟静默超时；
- 5 分钟内拒绝或要求修改时禁止写入和离线排队；
- 完整预览展示后 5 分钟没有回复时继续写入；
- 正文变化或收到含义不明的回复时不得沿用原倒计时；
- 固定模板包含适用条件、不适用条件、召回提示和预分类；
- review skill 只改分类，不改正文；
- capture 仍然只写 `inbox/`，不调用本地 GBrain CLI；
- 安装器重复运行保持幂等。

## 项目代码与本地配置同步

执行顺序固定如下：

1. 修改项目测试并验证 RED；
2. 修改项目安装器生成内容和接入文档；
3. 运行目标测试、类型检查和必要的项目校验；
4. 使用当前项目的 `install-client` 重新生成本地 Codex/OpenCode 规则；
5. 检查生成文件与项目常量一致；
6. 对不受安装器管理但仍在生效的旧 GBrain 写入技能进行兼容修订，确保它
   不能绕过写入前审核；
7. 保留本地文件中的非 GBrain 管理内容，不覆盖用户其他规则。

## 验收标准

- 项目生成源、测试、文档和本地配置表达同一套规则；
- 默认用户可见内容使用中文；
- 自动召回不会触发自动写入；
- 第 2 次独立同类故障必定进入错误总结；
- 用户明确同意，或完整预览展示后 5 分钟没有回复，才能调用 `put_page`；
- 每条经验都有明确的适用和不适用场景；
- 人工分类审核不修改已确认正文；
- 本地 Codex/OpenCode 不再保留可绕过门禁的旧写入说明。
